# WWII Journey, army choice and battle results

This release extends DSL's entry and learning flows without changing combat
rules, dice, opponent difficulty, map rendering or fog authority.

## Army choice

Solo setup has a **Your army** selector with the operation's faction names,
including RAF/Luftwaffe, Americans/Japanese and Soviets/Germans. The other army
is computer-controlled. The Allied seat still takes the first combat turn. If
the human chooses the Axis, the computer's opening turn resolves once during
creation, with its normal fog-filtered replay available. GET/reload never runs
that turn again. On preparation maps the computer plans and locks, then waits
for the human's lock before any combat turn resolves.

Named multiplayer setup offers:

| Choice | Assignment |
| --- | --- |
| Selected | Creator chooses either army; the invitation joins the other. |
| Random | Server chooses either creator army with equal probability. |
| Coin flip | One server toss: Heads assigns the Allied seat to the creator, Tails the Axis. The result is recorded and shown. |

The assignment is visible in waiting instructions and Battle options. The
lobby names the actual open army. Both commander recovery and MOVE codes stay
attached to the player's seat through rematches and army swaps. The database's
existing `host`/`guest` columns remain Allied/Axis seats; a vacant Allied seat is
valid. No schema migration or existing-match rewrite is needed.

Creation API additions: `side: "us" | "de"` and
`team_assignment: "selected" | "random" | "coin_flip"`. Omitted fields preserve
the old Allied-creator default. New explicit assignments track creator reset
authority across swaps; old invitations retain their existing reset behavior.
No client-provided toss result is accepted. Assignment is rolled once on POST,
stored, and never regenerated by reads.

## Battle result

A dismissible **Victory** or **Defeat** dialog names the winner, operation,
final round, authoritative outcome and public mission progress. It appears
after a live computer replay, once per battle/result in the current browser
tab. It can always be reopened from **View battle result** in Battle & reports.
The controls lead to final-board review, solo replay/multiplayer rematch,
Home, or the current Journey.

`battle_setup.result_summary` computes a public reason from authoritative
state; the client does not infer victory from visible enemy counters. It covers
objective holds, deadlines, army elimination, weighted control, linked fronts,
evacuation, carriers, RAF stations and resignation. The result does not expose
hidden enemy rosters or a fabricated enemy survivor count. Existing finished
saves also receive the new presentation.

## A fourteen-operation Journey

**Start WWII Journey** opens a chapter index. The selected Home Experience is
carried in, and can be changed before starting. Both army sides are available.
The stages are a skills progression using fictional tactical layouts, not a
chronological or historically exact campaign.

| Operation | Focus |
| --- | --- |
| Village Crossing | Selection, movement, attacks and the objective |
| Orchard Road | Cover, smoke, suppression, rally, overwatch |
| Stonebridge | Crossing, routes and AP |
| Riverfront Offensive | Platoons and officers |
| Relay Crossing | Observation, radio, mortars and supplies |
| Kharkov | Armor, ammunition, repairs and weighted flags |
| Shingle Cove | Private preparation, bunkers, naval fire and boats |
| Dunkirk | Rearguard and evacuation |
| Operation Iron Lantern | Commander airborne drops, beacons and Flak |
| Tidal Gate | Engineering and linked fronts |
| Midway | Fleet roles and sea control |
| Battle of Britain | Aircraft, interception and service |
| Fubar | Air/surface layers and combined operations |
| Operation Breakwater | Larger landing plan |

Chapters create separate solo battles and do not overwrite another match.
Unfinished chapters can resume through their saved browser seat. Wins and
defeats both record completion; chapters are never gated behind wins. Players
can jump ahead or replay a completed chapter. Chapter progress lives under
`ww2-journey-v1` in local storage. Losing browser storage loses this chapter
index, but normal SAVE/MOVE recovery continues to work. Journey/Experience
preferences are not embedded in SAVE codes.

## Field coach

The former in-battle learning guide is **Field coach**, under **View → Help**.
It remains optional in every DSL battle, and now works for signed-in commanders
as well as guests. Journey battles open it intentionally. Classic is unchanged.

| Experience | Instruction |
| --- | --- |
| Simple | Explains terms and controls, one action at a time. |
| Moderate | Assumes board-game familiarity; explains DSL choices and tradeoffs. |
| Expert | Costs, thresholds, interactions, timing and commitment boundaries. |

Switching Experience updates the current explanation without changing rules or
lesson progress. Simple/Moderate offer expandable exact detail. Expert does
not repeat basic explanations of turns or what a d6 is. A searchable topic
index supports direct review. Each topic has a practical task and **Show me**
navigation; specialist lessons can select an appropriate friendly unit to show
its controls. They never issue game orders or spend AP.

Topics are selected from the current operation's version flags and own roster,
never concealed enemy data. Coverage includes GUI navigation, Experience,
platoons, replay and recovery; all previous combat/terrain/support topics;
Observe and dated radio contacts; finite mortars and resupply; armored flags;
evacuation; reinforcement schedules; private deployment and lock; airborne
scatter/Flak/water arrivals; engineering, fleets and aircraft. Iron Lantern and
Fubar teach the modern airborne system; Carentan and Market Garden retain their
older reserve instructions. Allied drop lessons give the Axis appropriate
defensive tasks.

Per-battle coach progress remains at `ww2-learning-v2`, preserving existing
read/practiced topics. Only successful public actions mark practice; setup uses
a confirmed-order UI event because private planning deliberately has no public
action-history feed. Reading, skipping, pausing and resuming are always allowed.
Neither the Journey nor coach invents rewards or changes gameplay state.

## Verification

Rule/API coverage lives in `test_ww2_battle_setup.py`; the broader Python suite
also checks old saves, commander ownership, rematches, fog and replay behavior.
`ww2-journey-dom.cjs` loads the complete production page scripts into jsdom and
connects them to Flask's test client through `ww2-api-bridge.py`, using disposable
SQLite files and no listening sockets. It checks real DOM/API interactions,
all 22 maps × two armies × three Experiences, selectors, progress, assignments,
and result/replay behavior. This harness cannot verify pixel layout, touch,
browser rendering or native dialogs.

`ww2-journey-browser.cjs` adds real-browser coverage for small phone, landscape,
desktop, both multiplayer seats, assignment choices, chapter progress, coaching
and results. Existing learning-browser entry assertions now follow the chapter
chooser and signed-in access. The current session's browser launch was blocked
by socket restrictions and escalation was automatically rejected; these browser
suites must not be reported as passed for this release.

Reproduce the DOM gate with `jsdom` installed separately (it is not a production
requirement): set `NODE_PATH` to that installation's `node_modules`, put the
Flask/Gunicorn Python environment on `PATH`, then run
`node tests/ww2-journey-dom.cjs` from the repository root. Run the browser suite
with Playwright and `CHROMIUM_EXECUTABLE_PATH` in an environment allowing local
HTTP/browser processes.
